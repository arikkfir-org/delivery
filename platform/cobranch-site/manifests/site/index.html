Built in

Everything a team needs to ship, in one product

One model, one permission system and one API, from the first push to production. No plug-ins to stitch together, no second tool to learn.

Git hosting

Clone, fetch and push over HTTPS or SSH. A push returns only once Cobranch has recorded it, so everyone sees it at once.

Branches, not pull requests

A branch is the request to merge, with a computed status, reviews and a threaded chat whose messages point at lines of code.

AI review and agents

AI reviews every push. Agents take tasks, from implementing an issue to researching a change, on the model you pick: Claude, Gemini, Grok, GPT or DeepSeek.

Jobs

Jobs run on branch events, declared in /cobranch.yaml beside your code, each as a principal with only the permissions it asks for.

Delivery

A built-in GitOps controller. Every branch becomes an environment, sent to the clusters its name maps to; main is one more.

Issues

Issues belong to an organization and link to the branches that work on them, so each shows the other. Agents take them as tasks.

Organizations and permissions

Users, groups, agents, keys, apps and jobs are all principals, granted the same permissions. Sign in with any OpenID Connect provider.

One API

REST and GraphQL for everything the Console does, so your scripts and your agents work exactly as people do.

Opinionated

One way to do each thing, made complete

Cobranch picks a way and finishes it, instead of offering every option halfway.

Branches are the unit of work

Status, chat, reviews and environment hang off the branch itself.

Merging is explicit

A branch never merges itself; whoever moves the base is the one who merged.

Pushes are immediate

What you pushed is what everyone sees, the moment your push returns.

Everything is a principal

People and machines get the same permissions, and you can always tell which acted.

Organizations own everything

Repositories, issues and agents belong to an organization, never to one person.

The default branch is the boundary

Settings live as code, and take effect when they reach main.

Yours to run

Kubernetes-native, cloud-agnostic

Cobranch is one Helm chart. You bring the cluster, the domain and the identity provider; your code and your data stay with you.

  • Any cluster. One chart installs and upgrades every workload, migrations included.
  • Any bucket. Amazon S3, Google Cloud Storage, Azure Blob Storage or a volume of your own.
  • Any sign-in. Any OpenID Connect provider, with sign-up open, by domain or by invitation.
  • Open source. MIT licensed, built in the open on GitHub.
